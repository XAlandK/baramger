MCP Guide for the Martian Map Challenge

Which MCP servers can help us get Mars data for a safe Marswalk? Three are worth using. The famous astronomy MCPs are not a good fit, because they are made for stars and galaxies, not for the ground of Mars.

Date 14 November 2026 Status NASA, PDS and GDAL MCPs added for this project. Challenge NASA “Interplanetary Survival Guide: Martian Map”

Summary

The short answer

  • Use
    NASA-MCP-server for Mars Trek map tiles (R1) and space weather data.
  • Use
    NASA PDS MCP to find raw science data from Mars missions.
  • Use
    GDAL MCP to work with elevation maps, so we can plan a safe route.
  • Skip
    Astronomy and cosmology MCPs built on astroquery, SIMBAD, VizieR or Gaia. They do not cover the Mars surface.

Ranked by how much they help this project

The picks

Every feature must trace back to the five challenge resources (R1–R5). Anything else is a supplementary source (S), and we need the team's OK first (decision D2). The chips show how each MCP fits this rule.

1

NASA-MCP-server

By ProgramComputer · Community project, not made by NASA · TypeScript, needs Node.js 22+

One server for many public NASA data services. It is the only MCP we found that reads Mars Trek, which is one of the official challenge resources.

Gives us
  • Mars Trek map layers and tiles (WMTS)
  • DONKI space weather: solar flares, solar particle events and CMEs, for radiation safety
  • JPL Horizons, for Sun and planet positions at a given time
  • NASA Image and Video Library
Fit
R1 Mars Trek DONKI = S · needs D2
Watch out
The Mars rover photo tool uses a NASA API that is now archived, so it may not work. The InSight weather feed stopped in 2020. Most tools work without an API key.
Open the repository ↗
2

NASA-PDS/pds-mcp-server

Hosted by NASA's Planetary Data System team on GitHub · Python · MIT license

Searches the Planetary Data System, NASA's main archive for planet data. It covers more than 70 missions, 4,500 datasets and 700 instruments. You can search by mission, target, instrument or product ID.

Gives us
A way to find the original science files behind Mars Trek, such as HiRISE, CTX, CRISM and THEMIS products.
Fit
Finds data behind R1 Direct PDS files = S · needs D2
Watch out
It is a research release: 5 stars, no versioned releases yet. Its page does not confirm which Mars instruments it covers, so test it with Jezero products first.
Open the repository ↗
3

GDAL MCP or gis-mcp

Community projects · Python (Rasterio, PyProj, GeoPandas)

A tool, not a data source. It works on map files we already have. We can use it on the HiRISE and CTX elevation maps from Mars Trek to find steep or rough ground.

Gives us
Raster info, reprojection and statistics. gis-mcp also makes hillshade images.
Fit
Tool only · no new source Works on R1 DEMs
Watch out
A slope tool is planned, but it may not be ready yet. We can work out slope with Python and Rasterio instead. GIS tools expect Earth by default, so always set the Mars 2000 coordinate system (IAU 49900).
Open GDAL MCP on PyPI ↗

Things to watch out for

Archived API

The Mars Rover Photos API on api.nasa.gov is archived. Do not use the rover photo tools in NASA MCPs. Use the Perseverance raw images JSON API (R5) instead.

Needs team OK

DONKI and direct PDS files are not in the five resources. Tag them as S, with inResourceList: false, and wait for decision D2.

Gap

No MCP exists for USGS Astrogeology or HiRISE. USGS has a public data service with HiRISE image footprints, and an archive of about 2,600 elevation maps of human exploration zones.

How MCPs fit

MCPs help Claude while we build. The finished app should call the data sources itself. All of these MCPs are community or research projects, so check each one before we rely on it.

Add the MCPs to Claude Code

Run these from the Baramger project folder. They add each server for this project only. They add tools to Claude Code and do not download any Mars data.

1 · NASA-MCP-server Connected

claude mcp add nasa -- npx -y @programcomputer/nasa-mcp-server@latest

2 · NASA PDS MCP Connected

git clone --depth 1 https://github.com/NASA-PDS/pds-mcp-server.git ~/mcp-servers/pds-mcp-server
uv venv --python 3.13 ~/mcp-servers/pds-mcp-server/.venv
uv pip install --python ~/mcp-servers/pds-mcp-server/.venv/bin/python -e ~/mcp-servers/pds-mcp-server "fastmcp==2.14.7" "mcp<2"
claude mcp add pds -- ~/mcp-servers/pds-mcp-server/.venv/bin/python -m pds_mcp_server

3 · GDAL MCP Connected

claude mcp add gdal -e GDAL_MCP_WORKSPACES="$PWD/data" -- uvx --python 3.12 --from gdal-mcp==1.1.3 gdal --transport stdio
  • The version pins matter. fastmcp 4 uses a newer MCP protocol that this Claude Code version does not accept, so PDS is pinned to fastmcp 2.14.7.
  • GDAL MCP can only read files inside the project's data/ folder.
  • New MCP tools show up when you start a new Claude Code session.
